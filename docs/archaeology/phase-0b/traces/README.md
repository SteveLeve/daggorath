# Traces — capture procedure and source-derived outputs

**Phase 0b deliverable (d).**

## 1. Status: ROM tracing is blocked

No retail ROM image and no CoCo emulator were available in the environment this
phase ran in, and its network egress reaches package registries and GitHub only,
so neither could be legally or practically obtained here. The obstacle is
environmental, not legal reasoning about the Morgan grant.

Therefore:

- The `.trace` files in this directory are **source-derived traces produced by the
  Phase 0b reference slice**. They are a self-consistency and regression baseline.
- They are **not** ROM validation and must not be cited as such.
- Interpretation (what a trace means) is kept in this file. The `.trace` files
  themselves are raw output, regenerated by command, never edited by hand.

## 2. Source-derived traces in this directory

Each `.script` is a timestamped keystroke script; each `.trace` is the
corresponding output. Regenerate all of them with `make traces` (see
`../README.md`).

| Script | What it exercises | Expected observation |
|---|---|---|
| `t1-move-turn-look.script` | TURN RIGHT, two blocked MOVEs, TURN AROUND, LOOK | facing changes; both MOVEs are blocked at (16,11) facing east/west yet still pay exertion; heart rate falls 46 → 40 → 36 |
| `t2-forward-corridor.script` | MOVE forward twice then MOVE BACKWARD | (16,11) → (15,11) → (14,11) → (15,11); three exertion charges |
| `t3-burst-one-jiffy.script` | a full `TURN RIGHT` + CR delivered inside one jiffy | dispatched in a single `PLAYER` turn, confirming `PLAYER` drains the whole buffer |
| `t4-parser-edges.script` | `Z` (ambiguous), `MOVEX` (too long), bare `TURN` (missing argument), bare `M` (defaults forward) | three `???` outputs, then a successful forward step |
| `t5-keyboard-overrun.script` | 40 characters plus CR inside one jiffy | the 32-byte circular buffer wraps with no overflow check; the line that reaches the parser is truncated garbage and produces `???` |

Trace format: `jiffy <TAB> clock <TAB> event <TAB> detail`, with `clock` as
`hour:minute:second.tenth.jiffy`. Event kinds: `INIT`, `QUEUE`, `TASK`, `LINE`,
`TURN`, `MOVE`, `SOUND`, `EXERT`, `SYNC`, `LOOK`, `OUTPUT`, `FAINT`, `REVIVE`,
`UNIMPLEMENTED`. Counters are sampled when the event is emitted, so an
interrupt-phase event can show a pre-bump counter (spec deviation D-5).

## 3. ROM capture procedure (to run when a ROM is available)

This is written to be executed as-is later, so that the comparison is not
redesigned under time pressure.

### 3.1 Prerequisites to record first

1. ROM image: filename, SHA-256, size, and where it came from, including the
   rights basis for holding it. Add the row to [`../../../provenance/ledger.md`](../../../provenance/ledger.md) §1 **before**
   capturing anything.
2. Emulator: name, exact version/commit, and machine configuration (CoCo model,
   RAM size, clock rate, cartridge autostart). Prefer an emulator with a
   scriptable debugger and deterministic frame timing — MAME's `coco2`/`coco3`
   drivers with Lua scripting, or XRoar with its debugger, are the practical
   candidates.
3. Assemble the pinned listing with `lwasm`, hash the resulting cartridge image,
   and diff it against the retail ROM. Record the byte differences. This is the
   single most valuable measurement in the whole phase, because every
   source-derived claim in this pack inherits its uncertainty from the answer.

### 3.2 RAM watches

Use the addresses resolved from `CD.ASM` for the build under test. Sample every
interrupt (60 Hz):

| Symbol | Why |
|---|---|
| `JIFFY`, `TENTH`, `SECOND`, `MINUTE`, `HOUR`, `DAY` | clock |
| `SEED` (3 bytes) | RNG stream position |
| `MAZLND` (1024 bytes) | maze, captured once per level entry |
| `PROW`, `PCOL`, `PDIR`, `PPOW`, `PDAM`, `POBJWT` | player |
| `HEARTR`, `HEARTC`, `HBEATF`, `HEARTF`, `FAINT` | physiology and heartbeat |
| `KBDHDR`, `KBDTAL`, `KBDBUF` (32 bytes) | keyboard buffer and overrun |
| `LINBUF` (32 bytes), `LINPTR` | line editor |
| queue head pointers at `QUEBEG`, and each live TCB's `P.TCTIM`/`P.TCRTN` | task order and countdowns |
| `CMXLND` (60 bytes) | creature matrix, for `CREGEN` |
| `UPDATE`, `DSPMOD`, `NEWLUK` | display mode and pending redraw |

Also log: the PC on entry to `SCHED`'s dispatch (`JSR [P.TCRTN,U]`) to recover the
executed task order, and DAC/single-bit-sound writes with timestamps.

### 3.3 Input injection

Inject keystrokes at the PIA/`POLCAT` level at chosen jiffy numbers, not by
typing. The scripts in this directory are already in
`<jiffy> <KEY>` form and should be replayed verbatim so that the ROM trace and
the reference trace are directly comparable.

### 3.4 Capture set, in priority order

1. **Level-0 entry at several different clock times.** Dump `MAZLND` immediately
   after `NEWLVL` returns, plus `SEED` before and after `DGEN90`. Repeat at
   `SECOND` = 0, 1, 7, 30, 59. Expectation from source: the 1024 maze bytes are
   identical every time and the post-`DGEN90` seed differs; `SECOND = 0` must show
   256 draws, not none.
2. **Level re-entry.** Descend and return, dumping `MAZLND` and `SEED` each time.
   Expectation: the map is rebuilt identically; creature placement is not.
3. **The five-minute `CREGEN` boundary.** Watch `CMXLND` across the boundary and
   record when an incremented matrix entry becomes a live creature control block,
   including the case where the player leaves and re-enters the level. This is
   Phase 0's open blocker.
4. **Simultaneous expirations.** Arrange a jiffy on which jiffy-queue and
   minute-queue tasks both expire and record the executed task order. Expectation:
   jiffy queue first, then tenth, second, minute, hour; FIFO within a queue.
5. **Parser edge cases.** Replay `t4` and `t5`. Confirm the `???` behaviour, the
   dispatch-on-full-buffer behaviour at 32 characters, and the exact keyboard
   overrun outcome.
6. **MOVE/TURN/LOOK timing.** Replay `t1` and `t2` and measure the jiffy cost of
   the turn sweep and the half-step animation, which the listing cannot give
   (spec deviation D-4).
7. **Blocked MOVE.** Confirm that a blocked step still adds
   `(POBJWT >> 3) + 3` to `PDAM`.
8. **Sound.** Determine whether waveform generation consumes `SEED`
   (`SOUNDS:SNOISE`) and how long a creature sound blocks the foreground.

### 3.5 Comparison

For each capture, produce a trace in this directory's format and diff it against
the reference slice's trace for the same script. Report the **first divergence**
with the jiffy number and both sides' values. Never regenerate a stored baseline
to make a diff pass: a changed baseline must be justified by a source or ROM
finding recorded in `../reconciliation.md`.
